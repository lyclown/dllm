Kubernetes ​

本指南将帮助您在 Kubernetes 集群中启动并运行 LangFlow，步骤包括：

  • 在 Kubernetes 集群中安装 LangFlow 作为 IDE（用于开发）
  • 在 Kubernetes 集群中安装 LangFlow 作为独立应用程序（用于生产运行时工作负载）

LangFlow (IDE) ​ ​

该解决方案旨在为开发者提供一个完整的环境，以创建、测试和调试他们的流程。它包括API和UI。

先决条件 ​

  • Kubernetes 服务器
  • kubectl
  • Helm

第0步：准备一个 Kubernetes 集群 ​

我们在这个示例中使用 Minikube，但你可以使用任何 Kubernetes 集群。

  1. 创建一个 Minikube 的 Kubernetes 集群。

    bash
    minikube start
    1

  2. 设置 kubectl 使用 Minikube。

    bash
    kubectl config use-context minikube
    1

第一步. 安装 LangFlow Helm 图表 ​

  1. 添加仓库到 Helm。

    bash
    helm repo add langflow https://langflow-ai.github.io/langflow-helm-charts
helm repo update
    1
    2

  2. 在 langflow 命名空间中使用默认选项安装 LangFlow。

    bash
    helm install langflow-ide langflow/langflow-ide -n langflow --create-namespace
    1

  3. 检查 pods 的状态

    bash
    kubectl get pods -n langflow
    1
    plaintext
    NAME                                 READY   STATUS    RESTARTS       AGE
langflow-0                           1/1     Running   0              33s
langflow-frontend-5d9c558dbb-g7tc9   1/1     Running   0              38s
    1
    2
    3

Step 2. 访问 LangFlow ​

启用本地端口转发，以从本地机器访问 LangFlow。

shell
kubectl port-forward -n langflow svc/langflow-langflow-runtime 7860:7860
1

现在您可以通过 http://localhost:7860/ 访问 LangFlow。

LangFlow 版本 ​

要指定不同的 LangFlow 版本，您可以在 values.yaml 文件中设置 langflow.backend.image.tag 和 langflow.frontend.image.tag 的值。

yaml
langflow:
  backend:
    image:
      tag: "1.0.0a59"
  frontend:
    image:
      tag: "1.0.0a59"

Storage ​

默认情况下，图表将使用存储在本地持久化磁盘中的 SQLLite 数据库。如果您想使用外部的 PostgreSQL 数据库，可以在 values.yaml 文件中设置 langflow.database 值。

yaml
# 部署 postgresql。如果您已有现成的 postgresql 数据库，可以跳过此部分。
postgresql:
  enabled: true
  fullnameOverride: "langflow-ide-postgresql-service"
  auth:
    username: "langflow"
    password: "langflow-postgres"
    database: "langflow-db"

langflow:
  backend:
    externalDatabase:
      enabled: true
      driver:
        value: "postgresql"
      host:
        value: "langflow-ide-postgresql-service"
      port:
        value: "5432"
      database:
        value: "langflow-db"
      user:
        value: "langflow"
      password:
        valueFrom:
          secretKeyRef:
            key: "password"
            name: "langflow-ide-postgresql-service"
    sqlite:
      enabled: false

Scaling ​

您可以通过修改 values.yaml 文件中的 replicaCount 值来扩展 LangFlow 后端和前端服务的副本数量。

yaml
langflow:
  backend:
    replicaCount: 3
  frontend:
    replicaCount: 3
1
2
3
4
5

您可以独立扩展前端和后端服务。

要进行垂直扩展（增加 pod 的资源），您可以在 values.yaml 文件中设置 resources 的值。

yaml
langflow:
  backend:
    resources:
      requests:
        memory: "2Gi"
        cpu: "1000m"
  frontend:
    resources:
      requests:
        memory: "1Gi"
        cpu: "1000m"

LangFlow (Runtime) ​

运行时图表专为在生产环境中部署应用程序而设计。它注重稳定性、性能、隔离性和安全性，以确保应用程序可靠高效地运行。

在生产环境中，为一组流使用专用部署是实现细粒度资源控制的基础。

先决条件 ​

  • Kubernetes 服务器
  • kubectl
  • Helm

第0步. 准备一个 Kubernetes 集群 ​

按照与 LangFlow IDE 相同的步骤进行准备。

第一步：安装 LangFlow 运行时 Helm 图表 ​

  1. 添加仓库到 Helm。

    shell
    helm repo add langflow <https://langflow-ai.github.io/langflow-helm-charts>
helm repo update
    1
    2

  2. 在 langflow 命名空间中使用默认选项安装 LangFlow 应用。 如果您将流程打包在一个 docker 镜像中，可以在 values.yaml 文件或使用 --set 参数中指定镜像名称： 如果您希望从远程位置下载流程，可以在 values.yaml 文件或使用 --set 参数中指定 URL：

    shell
    helm install my-langflow-app langflow/langflow-runtime -n langflow --create-namespace --set image.repository=myuser/langflow-just-chat --set image.tag=1.0.0
    1
    shell
    helm install my-langflow-app langflow/langflow-runtime -n langflow --create-namespace --set downloadFlows.flows[0].url=https://raw.githubusercontent.com/langflow-ai/langflow/dev/src/backend/base/langflow/initial_setup/starter_projects/Basic%20Prompting%20(Hello%2C%20world!).json
    1

  3. 检查 pod 的状态。

    shell
    kubectl get pods -n langflow
    1

第2步. 访问 LangFlow 应用 API ​

启用本地端口转发，以便从本地机器访问 LangFlow。

shell
kubectl port-forward -n langflow svc/langflow-my-langflow-app 7860:7860
1

现在你可以通过 http://localhost:7860/api/v1/flows 访问 API 并执行流程：

shell
id=$(curl -s <http://localhost:7860/api/v1/flows> | jq -r '.flows[0].id')
curl -X POST \
    "<http://localhost:7860/api/v1/run/$id?stream=false>" \
    -H 'Content-Type: application/json' \
    -d '{
      "input_value": "Hello!",
      "output_type": "chat",
      "input_type": "chat"
    }'

日志级别和 LangFlow 配置 ​

您可以在 values.yaml 文件中设置日志级别和其他 LangFlow 的配置。

yaml
env:
  - name: LANGFLOW_LOG_LEVEL
    value: "INFO"
1
2
3

配置密钥和变量 ​

要注入密钥和 LangFlow 全局变量，可以在 values.yaml 文件中使用 secrets 和 env 部分。

假设您的流程使用了一个作为密钥的全局变量；当您将该流程导出为 JSON 时，建议不要包括它。 在 LangFlow 运行时导入流程时，可以在 values.yaml 文件中的 env 部分中设置全局变量。 假设您有一个名为 openai_key_var 的全局变量，您可以直接从密钥中读取它：

yaml
env:
  - name: openai_key_var
    valueFrom:
      secretKeyRef:
        name: openai-key
        key: openai-key
