Tool components in Langflow ​

工具通常通过 Tools 端口连接到 agent 组件。Agents 使用大型语言模型（LLM）作为推理引擎，以决定使用哪个连接的工具组件来解决问题。

在 agentic 功能中，工具本质上是代理可以调用的函数，用于执行任务或访问外部资源。一个函数被包装为一个 Tool 对象，并具有 agent 能理解的通用接口。通过工具注册，代理可以知道工具的存在，通常是在代理初始化时，代理会被提供一份可用工具的列表。Tool 对象的描述告诉代理这个工具可以做什么。

然后，代理使用连接的 LLM 来推理问题，以决定哪个工具最适合完成工作。

在流程中使用工具 ​

工具通常通过工具端口连接到代理组件。

简单代理启动项目使用 URL 和计算器工具连接到代理组件，以回答用户的问题。OpenAI LLM 作为代理的大脑，用于决定使用哪个工具。

要将组件转化为代理可使用的工具，请在组件中启用工具模式。启用工具模式会修改组件输入，以接受来自代理的调用。如果您想连接到代理的组件没有工具模式选项，您可以修改组件的输入以使其成为工具。有关示例，请参见将任意组件变为工具。

Astra DB 工具 ​

Astra DB Tool 允许代理连接到 Astra DB 集合并查询数据。

Inputs ​

名称类型描述
Tool NameString在代理的提示中引用工具所用的名称。
Tool DescriptionString工具的简要描述。这有助于模型决定何时使用它。
Collection NameString要查询的 Astra DB 集合的名称。
TokenSecretString用于访问 Astra DB 的身份验证令牌。
API EndpointStringAstra DB 的 API 端点。
Projection FieldsString要返回的属性，使用逗号分隔。默认值："*"。
Tool ParametersDict模型需要填写的工具执行参数。对于必填参数，使用感叹号标记（例如，!customer_id）。
Static FiltersDict用于过滤查询结果的属性-值对。
LimitString要返回的文档数量。

Outputs ​

数据输出主要用于直接查询 Astra DB 时，而工具输出则用于与 LangChain 代理或链进行集成时。

名称类型描述
DataList[Data]包含从 Astra DB 查询结果的 Data 对象列表。每个 Data 对象包含由投影属性指定的文档字段。受 number_of_results 参数限制。
ToolStructuredTool一个 LangChain StructuredTool 对象，可用于代理工作流。包含工具名称、描述、基于工具参数的参数架构以及查询函数。

Astra DB CQL 工具 ​

Astra DB CQL Tool（Astra DB CQL 工具）使代理可以从 Astra DB 的 CQL 表中查询数据。

这个工具与 Astra DB Tool（Astra DB 工具）的主要区别在于，该工具专为 CQL 表设计，并需要分区键（partition keys）进行查询，同时也支持聚类键（clustering keys）以进行更具体的查询。

Inputs ​

名称类型描述
Tool NameString在代理的提示中用于引用工具的名称。
Tool DescriptionString工具的简要描述，用于指导模型使用它。
KeyspaceStringkeyspace 的名称。
Table NameString要查询的 Astra DB CQL 表的名称。
TokenSecretStringAstra DB 的认证令牌。
API EndpointStringAstra DB 的 API 端点。
Projection FieldsString要返回的属性，以逗号分隔。默认值："*"。
Partition KeysDict模型必须填写的必需参数，以便查询工具。
Clustering KeysDict模型可以填写的可选参数以优化查询。必需参数应标记为感叹号（例如，!customer_id）。
Static FiltersDict用于过滤查询结果的属性-值对。
LimitString要返回的记录数。

Outputs ​

NameTypeDescription
DataList[Data]包含来自 Astra DB CQL 表的查询结果的 Data 对象列表。每个 Data 对象包含由投影字段（projection fields）指定的文档字段。结果数量受 number_of_results 参数限制。
ToolStructuredTool一个可用于代理工作流程（agent workflows）的 LangChain StructuredTool 对象。包含工具名称、描述、基于分区和聚簇键的参数架构，以及查询函数。

MCP 工具（stdio） ​

该组件通过 stdio 连接到 Model Context Protocol (MCP) 服务器，并将其工具作为 Langflow 工具暴露给 Agent 组件使用。

要使用 MCP stdio 组件，请按照以下步骤操作：

  1. 将 MCP stdio 组件添加到您的工作流中，并将其连接到一个 agent。流程如下：

  1. 在 MCP stdio 组件中的 mcp command 字段，输入启动您的 MCP 服务器的命令。对于 Fetch 服务器，该命令为：

    shell
    uvx mcp-server-fetch
    1

  2. 打开 Playground。请求代理总结最近的技术新闻。代理将调用 MCP 服务器函数 fetch 并返回摘要。这表明 MCP 服务器已连接并正常工作。

Inputs ​

名称类型描述
commandStringMCP（消息通信协议）命令（默认值：uvx mcp-sse-shim@latest）

输出 ​

名称类型描述
toolsList[Tool]MCP 服务器暴露的工具列表

MCP 工具 (SSE) ​

该组件通过 SSE (Server-Sent Events, 服务器发送事件) 连接到 Model Context Protocol (MCP, 模型上下文协议) 服务器，并将其工具作为 Langflow 工具暴露，以便由 Agent 组件使用。

要使用 MCP SSE 组件，请按照以下步骤操作：

  1. 将 MCP SSE 组件添加到您的工作流程中，并将其连接到一个 agent。该流程类似于 MCP stdio 组件流程。

  2. 在 MCP SSE 组件中，在 url 字段中输入当前 Langflow 服务器的 mcp/sse 端点的 URL。 这将从 Langflow 服务器获取所有当前可用的工具。

Inputs ​

名称类型描述
urlStringSSE URL（默认：http://localhost:7860/api/v1/mcp/sse）

输出 ​

名称类型描述
toolsList[Tool]MCP 服务器提供的工具列表
